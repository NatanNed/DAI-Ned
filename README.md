# DAI-Ned — Інформаційна система ДАІ

GUI-додаток для інформаційної системи підтримки діяльності **Державної автомобільної інспекції**.  
Дозволяє вести облік транспортних засобів, водіїв, власників, номерних знаків і **штрафів**, а також виконувати пошук по записах.

Реалізовано на **JavaFX** + **JDBC** + **PostgreSQL** за архітектурним патерном **MVC** з виділеним сервісним шаром.

> Курсовий проєкт з GUI-програмування.

## ✨ Функціонал

Над основною таблицею **`fines`** (штрафи) реалізовано повний набір операцій:

- ➕ **Create** — додавання нового штрафу через форму введення
- 📖 **Read** — перегляд списку всіх штрафів у таблиці результатів
- ✏️ **Update** — редагування обраного запису
- 🗑 **Delete** — видалення запису з підтвердженням
- 🔍 **Search** — пошук штрафів за заданими критеріями

Усі SQL-запити виконуються через **`PreparedStatement`** — це захищає від SQL-ін'єкцій і коректно обробляє параметри будь-яких типів.

## 🏛 Архітектура

Проєкт побудовано за патерном **MVC** з додатковим сервісним шаром:

| Шар | Призначення |
|---|---|
| **Model** | POJO-класи предметної області (`Fine`, `Person`, `Vehicle` тощо) |
| **View** | JavaFX-інтерфейс: FXML-розмітка, форми, таблиці, діалоги |
| **Controller** | Обробка дій користувача, валідація вводу, зв'язок View ↔ Service |
| **Service** | JDBC-операції з БД, бізнес-логіка, побудова SQL-запитів |

## 🚀 Збірка та запуск

### Вимоги
- JDK 21+ (рекомендовано 26)
- Maven 3.8+
- PostgreSQL 16+

### Налаштування БД
1. Створи базу:
```sql
   CREATE DATABASE dai_ned;
```
2. Виконай скрипт схеми:
```bash
   psql -U postgres -d dai_ned -f sql/schema.sql
```
3. Пропиши свої креди у `src/main/resources/db.properties`:
```properties
   db.url=jdbc:postgresql://localhost:5432/dai_ned
   db.user=postgres
   db.password=<твій_пароль>
```

### Запуск
```bash
cd dai-system-nedaykhlib
mvn clean javafx:run
```

Або зі збіркою jar:
```bash
mvn clean package
java -jar target/dai-system-nedaykhlib-1.0.jar
```

## 🌿 Правила роботи з Git

### Гілки
- `master` — стабільна, релізна. Сюди потрапляє лише перевірений код.

- ### Workflow
1. Створюємо гілку від `dev`: `git checkout -b feature/<назва> dev`
2. Робимо коміти за правилами вище.
3. Пушимо: `git push -u origin feature/<назва>`
4. Відкриваємо **Pull Request** у `dev`, самостійно перевіряємо й мерджимо.
5. Після завершення фічі — мерджимо `dev` → `master` з тегом версії (напр. `v1.0`).

### Що **не** комітимо
Файл `.gitignore` виключає:
- `target/`, `out/`, `build/`
- `.idea/`, `*.iml`
- `db.properties` з реальними паролями
- логи, тимчасові файли
